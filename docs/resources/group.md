# circleci_group (Resource)

Manages a CircleCI group. A group is a named collection of organization members that project and context permissions can be granted to.

## Availability

| CircleCI Cloud | CircleCI Server |
|---|---|
| yes | **no** |

Groups require a `circleci` type (standalone) organization. The API documents
group creation as "currently only supported for standalone organizations", and a
CircleCI Server installation is always a `github` type organization, so this is
Cloud only.

-> **Managing who is in a group** This resource manages the group itself. Use
[`circleci_group_membership`](./group_membership) to manage its members, and
[`circleci_project_group`](./project_group) to grant a group a role on a project.

~> **Groups cannot be updated in place** The API has no update endpoint, so
every attribute forces replacement: changing `name` or `description` destroys
the group and creates a new one with a new `id`. Any permissions and members
attached to the old group are lost with it.

## Example Usage

```terraform
resource "circleci_group" "developers" {
  organization_id = "00000000-0000-0000-0000-000000000000"
  name            = "developers"
  description     = "Engineers who deploy to staging"
}
```

## Schema

### Required

- `name` (String) Name of the group. Changing this value forces a new resource to be created.
- `organization_id` (String) Unique identifier (UUID) of the organization the group belongs to. Changing this value forces a new resource to be created.

### Optional

- `description` (String) Description of the group. Changing this value forces a new resource to be created.

### Read-Only

- `id` (String) Unique identifier (UUID) of the group.

## Import

Import is supported using `organization_id/group_id`. A group id is only unique
within its organization, so both are required:

```shell
terraform import circleci_group.developers "<organization_id>/<group_id>"
```
