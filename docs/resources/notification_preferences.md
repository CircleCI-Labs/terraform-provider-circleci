# circleci_notification_preferences (Resource)

Manages a sparse set of CircleCI notification preference toggles, for the calling user or for a project.

## Availability

| CircleCI Cloud | CircleCI Server |
|---|---|
| yes | **no** |

Preferences are served by the CircleCI v3 API, which CircleCI Server does not route to its public API service.

## A settings resource, not a thing that gets created

The preference matrix is a fixed, CircleCI-defined catalog that exists for as long as the user or project does, seeded with CircleCI's defaults. There is no route to add, remove or reset a row. That shapes how this resource behaves, in the same way as `circleci_organization_settings`:

- **`updates` is a map, keyed by preference id, and is `Optional` only — never `Computed`.** A preference id left out of the map is not written, so CircleCI keeps whatever value it already has. Several `circleci_notification_preferences` resources may therefore manage disjoint rows of the same matrix.
- **`preferences` reports the full catalog**, including rows this configuration does not manage, so the ids `updates` needs can be discovered from `terraform plan` or `terraform state show` after a first apply that sets no toggles.
- **Removing a key from `updates` stops managing that row; it does not revert it.** There is no route that restores a CircleCI default, so the row keeps the value Terraform last applied. The provider emits a warning when this happens.
- **Destroy removes the resource from Terraform state and makes no API call.** Every managed row keeps its current value.

## Example Usage

```terraform
# Manage a couple of the calling user's own notification preferences by id.
# Any preference id not listed in `updates` is left exactly as CircleCI has
# it. Discover ids from `preferences` in state after a first apply that sets
# no toggles, e.g. `terraform apply` with an empty `updates = {}`, then
# `terraform state show circleci_notification_preferences.mine`.
resource "circleci_notification_preferences" "mine" {
  scope = "user"

  updates = {
    "33333333-3333-3333-3333-333333333333" = false
    "44444444-4444-4444-4444-444444444444" = true
  }
}

# The same, scoped to a project instead of the calling user.
resource "circleci_notification_preferences" "project" {
  scope      = "project"
  project_id = "11111111-1111-1111-1111-111111111111"
  org_id     = "00000000-0000-0000-0000-000000000000"

  updates = {
    "55555555-5555-5555-5555-555555555555" = false
  }
}

# The full preference catalog, including rows this configuration does not
# manage, so their ids can be found for a future `updates` entry.
output "my_preference_catalog" {
  value = circleci_notification_preferences.mine.preferences
}
```

## Schema

### Required

- `scope` (String) Whether this manages the calling user's own preferences (`user`) or a project's preferences (`project`). `project_id` and `org_id` are required when this is `project`, and must be omitted when this is `user`. Changing this value forces a new resource to be created.

### Optional

- `org_id` (String) Unique identifier (UUID) of the organization the project belongs to. Required when `scope = "project"`. Changing this value forces a new resource to be created.
- `project_id` (String) Unique identifier (UUID) of the project whose preferences these are. Required when `scope = "project"`. Changing this value forces a new resource to be created.
- `updates` (Map of Boolean) The preference rows to manage, keyed by preference id (see `preferences[*].id` after a first apply) and mapping to the desired `is_enabled` value.

Leave a preference id out to let CircleCI manage it; the provider only writes rows that appear in this map. Removing a key stops managing that row without reverting it, since there is no route that restores a CircleCI default.

### Read-Only

- `preferences` (Attributes List) The full preference matrix CircleCI reports for this scope, including rows `updates` does not manage. (see [below for nested schema](#nestedatt--preferences))

### Nested Schema for `preferences`

Read-Only:

- `channel` (String) The delivery channel this row's `is_enabled` applies to, for example `email`.
- `display_order` (Number) Display order of the preference within its group.
- `entity_scope` (String) The preference's own scope attribute (for example `actor`), distinct from this resource's `scope`.
- `experimental` (Boolean) Whether CircleCI flags this preference as experimental.
- `group_id` (String) Unique identifier (UUID) of the preference's group.
- `group_name` (String) Display name of the preference's group.
- `id` (String) Unique identifier (UUID) of the preference row. This is the key `updates` uses.
- `is_enabled` (Boolean) The current value CircleCI reports for this row.
- `name` (String) Display name of the preference.
- `section_id` (String) Unique identifier (UUID) of the preference's section, when it belongs to one; null otherwise.
- `section_name` (String) Display name of the preference's section, when it belongs to one; null otherwise.
- `user_configurable` (Boolean) Whether this row's `is_enabled` may be changed at all; some rows are informational only and reject a write from `updates`.
