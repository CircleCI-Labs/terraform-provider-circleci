# circleci_organization_contacts (Resource)

Manages a CircleCI organization's technical (primary) and security contact email lists.

## Availability

| | |
| --- | --- |
| **CircleCI Cloud** | Yes |
| **CircleCI Server** | No — served by an unofficial `/api/private` route with no published specification. A Server installation's gateway does not route `/api/private` at all, so using this with `deployment = "server"` reports an explicit error rather than the confusing HTTP 404 the request would otherwise produce. |
| **API** | `GET` and `PUT /api/private/organization/{org_id}/contacts` |
| **Organization type** | Any. |
| **Token** | A personal API token belonging to an organization admin. |

~> **This route carries no published specification and CircleCI may change or remove it without notice.** It is not part of the versioned public API. Treat it as best-effort, the same caution CircleCI's own org-migration tooling documents for it.

## A settings resource, not a thing that gets created

Both contact lists exist for as long as the organization does, defaulting to empty. That shapes how this resource behaves, in the same way as `circleci_organization_settings`:

- **`primary_contacts` and `security_contacts` are both `Required`, not sparse.** The underlying route is a single `PUT` that replaces both lists together; there is no way to update one list while leaving the other alone. This resource therefore owns both lists in full — a value it does not send is a value it clears, not a value it leaves alone.
- **Both are sets, not lists.** CircleCI does not preserve the order addresses were submitted in, and reports them back in an order of its own choosing. A plan compares sets without regard to order, so this never shows a spurious change the way declaring them as ordered lists would.
- **Each list holds at most 5 addresses.** CircleCI rejects a write that would exceed that.
- **Destroy removes the resource from Terraform state and makes no API call.** CircleCI has no route that resets a contact list, so both lists keep the values Terraform last applied.

## Example Usage

```terraform
# Both lists are sets: CircleCI does not preserve the order addresses were
# submitted in, so order here does not matter and will never show as a change.
resource "circleci_organization_contacts" "example" {
  org_id = "00000000-0000-0000-0000-000000000000"

  primary_contacts = [
    "platform-team@example.com",
    "jane.doe@example.com",
  ]

  security_contacts = [
    "security@example.com",
  ]
}
```

## Schema

### Required

- `org_id` (String) Unique identifier (UUID) of the organization these contact lists belong to. Changing this value forces a new resource to be created, rather than moving management to a different organization's existing lists.
- `primary_contacts` (Set of String) Technical (primary) contact email addresses for the organization. At most 5; CircleCI rejects a write that would exceed that.

This is a set, not a list: CircleCI does not preserve the order addresses were submitted in, and reports them back in an order of its own choosing. Declaring this as an ordered list would show a difference on every plan with nothing to apply, the same bug fixed for `circleci_webhook`'s `events`.
- `security_contacts` (Set of String) Security contact email addresses for the organization. At most 5; CircleCI rejects a write that would exceed that.

This is a set, not a list: CircleCI does not preserve the order addresses were submitted in, and reports them back in an order of its own choosing. Declaring this as an ordered list would show a difference on every plan with nothing to apply, the same bug fixed for `circleci_webhook`'s `events`.
