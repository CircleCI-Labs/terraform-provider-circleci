# circleci_user_collaborations (Data Source)

Lists the organizations the configured API token can collaborate on, with the CircleCI ID and slug of each.

This is the discovery counterpart to the rest of the provider. Almost every CircleCI resource is keyed by `organization_id` — a UUID that is otherwise only visible in the web UI — and the Insights data sources need an organization *slug*. This is the one way to obtain either from Terraform, rather than pasting a UUID into a variable and hoping it is the right one.

## Availability

| | |
| --- | --- |
| **CircleCI Cloud** | Yes |
| **CircleCI Server** | Yes — the route is v2, which CircleCI Server serves. |
| **API** | `GET /api/v2/me/collaborations` |
| **Organization type** | Any; the listing spans every VCS type the user is connected to. |
| **Token** | A **personal** API token. The route reports the authenticated user's collaborations, so a project or organization token is rejected. |

## The set is broader than "my organizations"

CircleCI assembles this list from three places, so it contains more than the organizations the user is a member of:

- organizations the user belongs to, across every connected VCS
- the **owner of any repository the user collaborates on**, even without belonging to that organization
- the user's own personal account

Filter on `vcs_type` when only standalone (`circleci`) organizations are wanted.

## `id` can be null

~> **An organization that CircleCI does not know yet has no ID.** Because the list is assembled partly from the VCS, an organization that exists on GitHub or Bitbucket but has never been used on CircleCI appears here with `id = null`. Such an organization cannot be referenced by any other resource until it has been onboarded, so a configuration that maps names to IDs should skip the null entries — `if c.id != null` — rather than assume every row is usable.

The ID is genuinely `null` rather than an empty string, so `c.id != null` is a reliable test.

## No pagination

The route is not paginated: CircleCI builds the whole set per request by fanning out to each connected VCS. There is no page token to follow and no arguments to narrow the listing by, which is why this data source takes none.

## Example Usage

```terraform
# Every organization the configured token can reach, with the UUID and slug of
# each. Nearly every CircleCI resource is keyed by organization_id, a UUID that is
# otherwise only visible in the web UI, so this is the way to discover one from
# Terraform.
data "circleci_user_collaborations" "mine" {}

# Standalone organizations only, and only the ones CircleCI already knows about: an
# organization that exists on the VCS but has never been used on CircleCI reports a
# null id and cannot be referenced by other resources yet.
locals {
  standalone_orgs = {
    for c in data.circleci_user_collaborations.mine.collaborations :
    c.name => c.id
    if c.vcs_type == "circleci" && c.id != null
  }
}

output "standalone_organization_ids" {
  value = local.standalone_orgs
}

# Look one up by name and use its UUID directly.
data "circleci_organization_settings" "acme" {
  org_id = local.standalone_orgs["acme"]
}

# The slug is what the Insights data sources take, and it is not the same shape as
# a project slug.
locals {
  org_slugs = {
    for c in data.circleci_user_collaborations.mine.collaborations :
    c.name => c.slug
  }
}

data "circleci_insights_summary" "acme" {
  organization_slug = local.org_slugs["acme"]
}
```
