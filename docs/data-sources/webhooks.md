# circleci_webhooks (Data Source)

Fetches every outbound webhook configured on a CircleCI project, including
webhooks created outside Terraform. Use [`circleci_webhook`](webhook) to fetch one
webhook by id, and [`circleci_webhook`](../resources/webhook) to manage one.

## Availability

| CircleCI Cloud | CircleCI Server |
|---|---|
| yes | yes |

Webhooks are served by the v2 API, which both deployments provide.

~> **Signing secrets are not returned.** CircleCI masks every signing secret, so
this data source reports only *whether* one is set, as `has_signing_secret`. Do
not try to read a receiver credential back out of it.

## Example Usage

```terraform
data "circleci_webhooks" "project" {
  project_id = "00000000-0000-0000-0000-000000000000"
}

output "circleci_webhook_urls" {
  value = [for webhook in data.circleci_webhooks.project.webhooks : webhook.url]
}

# Webhooks that would deliver payloads without verifying the receiver's
# certificate, or without signing the payload at all.
output "circleci_insecure_webhooks" {
  value = [
    for webhook in data.circleci_webhooks.project.webhooks : webhook.name
    if !webhook.verify_tls || !webhook.has_signing_secret
  ]
}
```

## Schema

### Required

- `project_id` (String) Unique identifier (UUID) of the project whose webhooks are listed. This is the webhook scope id; `project` is the only scope type the API supports.

### Read-Only

- `webhooks` (Attributes List) The webhooks on the project, in the order the API returns them. (see [below for nested schema](#nestedatt--webhooks))

### Nested Schema for `webhooks`

Read-Only:

- `created_at` (String) Timestamp the webhook was created, as the API reported it.
- `events` (List of String) Events that trigger delivery, such as `workflow-completed` and `job-completed`.
- `has_signing_secret` (Boolean) Whether a signing secret is configured. The secret itself is masked by the API and is never available here.
- `id` (String) Unique identifier (UUID) of the webhook.
- `name` (String) Name of the webhook.
- `scope_id` (String) Unique identifier (UUID) of the scope the webhook watches, which is the project id.
- `scope_type` (String) Type of the scope the webhook watches. Always `project`.
- `updated_at` (String) Timestamp the webhook was last updated, as the API reported it.
- `url` (String) URL webhook payloads are delivered to.
- `verify_tls` (Boolean) Whether CircleCI verifies the receiver's TLS certificate when delivering a payload.

## Notes

* `project_id` is the webhook *scope id*. `project` is the only scope type the
  API supports, and it is reported back as `scope_type` on each webhook.
* Event names keep their hyphens — `workflow-completed`, `job-completed` — even
  though the surrounding JSON keys do not.
* Pagination is followed internally. The webhook service does not paginate today,
  but the response carries the page token, so the whole collection is covered
  either way.
* `webhooks` is always a list, empty when the project has none, so configurations
  can iterate over it unconditionally.
