# circleci_job (Data Source)

Fetches one CircleCI job by project slug and job number.

~> **This is a point-in-time read of mutable runtime state.** `status`, timestamps and `parallel_runs`
change while the job runs. Use this data source for inspection and in `check` blocks; using it to derive
a resource attribute will cause a perpetual diff.

-> **Addressed by number, not by the id the API reference documents.** The CircleCI v2 API reference
documents `GET /api/v2/jobs/{id}`, but that route is a bare reverse-proxy pass-through to the API
(via the API) with no CircleCI Server equivalent: the API does not exist there, and the
route is entirely absent from CircleCI Server's gateway routes served. `GET
/api/v2/project/{slug}/job/{job-number}` is used instead — it is implemented by the API, which
*is* deployed on CircleCI Server and routed there. That is why `project_slug` and `job_number`, not a job
id, identify a job here.

Per-step detail (each parallel run's individual steps) and artifacts/test results are not exposed: they
are unbounded, per-build detail that would make this data source read as a partial build log rather than
a job summary. Use the CircleCI web UI or the REST API directly for those.

## Availability

| | |
| --- | --- |
| **CircleCI Cloud** | Yes |
| **CircleCI Server** | Yes — the API is deployed and routed on both. |
| **API** | `GET /api/v2/project/{project-slug}/job/{job-number}` |
| **Organization type** | Any. |
| **Token** | Any valid API token with permission to view the project's builds. |

## Example Usage

```terraform
# Fetches a job by project slug and job number. Available on both
# CircleCI Cloud and CircleCI Server.
data "circleci_job" "this" {
  project_slug = "gh/CircleCI-Public/api-preview-docs"
  job_number   = 578122
}

check "job_used_expected_resource_class" {
  assert {
    condition     = data.circleci_job.this.resource_class == "medium"
    error_message = "Job ${data.circleci_job.this.name} ran on ${data.circleci_job.this.resource_class}, not medium."
  }
}
```

## Schema

### Required

- `job_number` (Number) The job's number, unique within its project.
- `project_slug` (String) The project's slug, e.g. `gh/CircleCI-Public/api-preview-docs`, or `circleci/<org-id>/<project-id>` for a GitLab, GitHub App or GitHub Server project.

### Read-Only

- `contexts` (List of String) Names of the contexts used by the job.
- `created_at` (String) When the job was created, as an RFC 3339 timestamp. Null for a job whose creation time was not recorded.
- `duration_ms` (Number) Duration of the job in milliseconds. Null while the job is still running.
- `executor_type` (String) Executor type the job ran on, e.g. `docker`. Null until the job has been dispatched.
- `name` (String) Name of the job, as declared in configuration.
- `organization_name` (String) Name of the organization owning the job's project.
- `parallel_runs` (Attributes List) Status of each parallel run ('task') of the job. Empty until the job has been dispatched. (see [below for nested schema](#nestedatt--parallel_runs))
- `parallelism` (Number) Number of parallel runs the job has.
- `pipeline_run_id` (String) Unique identifier (UUID) of the pipeline run this job belongs to. See [`circleci_pipeline_run`](pipeline_run).
- `queued_at` (String) When the job was placed in a queue, as an RFC 3339 timestamp. Null while the job is still queued or has not been queued yet.
- `resource_class` (String) Resource class the job ran on. Null until the job has been dispatched.
- `started_at` (String) When the job started running, as an RFC 3339 timestamp. Null while the job has not started.
- `status` (String) Current status of the job.
- `stopped_at` (String) When the job stopped, as an RFC 3339 timestamp. Null while the job is still running.
- `web_url` (String) URL of the job in the CircleCI web UI.
- `workflow_id` (String) Unique identifier (UUID) of the workflow this job was most recently part of. See [`circleci_workflow`](workflow).
- `workflow_name` (String) Name of the workflow this job was most recently part of.
